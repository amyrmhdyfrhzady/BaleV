# نمونه آزمایشی اتصال مستقیم Runnerها (GitHub Actions)

## وضعیت مهم
این بسته **انتقال کامل ویندوز یا RAM را پیاده‌سازی نمی‌کند**. این یک مرحلهٔ پیش‌نیاز است که بررسی می‌کند آیا دو GitHub-hosted runner در شرایط واقعی شما می‌توانند اتصال TCP مستقیم برقرار کنند یا نه. تا وقتی این تست موفق نشده و یک دیسک VM سازگار در هر دو سمت در دسترس نباشد، شروع انتقال QEMU امن نیست.

GitHub اعلام می‌کند nested virtualization روی hosted runnerها رسماً پشتیبانی نمی‌شود و آزمایشی است. Runnerها نیز ماشین‌های موقت‌اند. به‌علاوه، listener روی پورت TCP لزوماً از اینترنت قابل‌دسترسی نیست؛ داشتن IP عمومی به معنی باز بودن inbound نیست.

## فایل‌ها
- `.github/workflows/target-listener.yml`: یک listener آزمایشی روی Runner مقصد راه می‌اندازد.
- `.github/workflows/source-connect-test.yml`: از Runner مبدأ به `target_host:target_port` اتصال می‌زند و یک payload آزمایشی می‌فرستد.
- `scripts/tcp_probe.py`: listener/client ساده برای تست مسیر شبکه.

## روش آزمایش
1. این فایل‌ها را در ریشهٔ یک repository قرار دهید.
2. در Actions، workflow با نام **Direct Runner - Target Listener Probe** را اجرا کنید.
3. در لاگ target، IP خروجی Runner را ببینید. این IP فقط برای تشخیص است؛ قابل‌دسترسی بودن inbound را تضمین نمی‌کند.
4. workflow با نام **Direct Runner - Source Connect Test** را اجرا کنید و `target_host` و `target_port` را وارد کنید.
5. فقط اگر اتصال واقعاً برقرار شد، می‌توان طراحی QEMU migration را در همان مسیر شبکه آزمایش کرد.

## محدودیت‌ها و ایمنی
- این آزمایش هیچ Windows ISO یا دیسک VM دانلود نمی‌کند.
- هیچ Artifact، Cache، سرویس ذخیره‌سازی یا Relay برای انتقال داده استفاده نمی‌شود.
- Listener فقط پیام آزمایشی کوتاه می‌پذیرد و دادهٔ VM دریافت نمی‌کند.
- هر workflow حداکثر 20 دقیقه اجرا می‌شود؛ برای آزمایش، listener را با workflow دستی دیگر متوقف کنید یا منتظر پایان timeout بمانید.
- برای اجرای واقعی QEMU، باید دیسک VM در مقصد به‌صورت سازگار موجود باشد و نسخه/پارامترهای QEMU و دستگاه‌های مجازی تطبیق داشته باشند. انتقال RAM به‌تنهایی جایگزین هماهنگ‌سازی دیسک نیست.
- این بسته در محیط GitHub شما اجرا نشده است؛ فقط فایل‌های آن ساخته شده‌اند. نتیجهٔ واقعی باید از لاگ‌های Actions مشخص شود.
